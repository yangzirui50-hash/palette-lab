视觉焦点：30 图双人独立试标（开发数据，非准确率验收）

目的：先确认“焦点”定义能否被两个人稳定理解，找出分歧类型，再决定是否值得扩大到独立保留集。不要将工具生成、AI 推测或算法热图作为人工答案。

你现在只需：
1. 你打开“评审A.html”，另一位没有看过你的答案的人打开“评审B.html”。各自在电脑浏览器中双击打开，保持 images 文件夹与 HTML 在一起；也可以复制整包给对方。无需启动服务器或上传图片。
2. 两人分开看原图，不讨论答案、不看 Palette Lab 热图。两份页面的前 5 张使用相同图片、不同顺序，先做这 5 张即可比较标注定义；其余图片也有独立顺序。每图选“单一／多个／分散纹理／均匀无焦点”。单一画 1 框；多个各画独立框（2–5 个）；后两类不画框。不确定可以正常记录，不要为了凑完整而猜。
3. 框住最先吸引注意的区域，而非机械框全物体。没有指定观看任务，按普通观看判断。人脸、文字或灯光哪个重要，都由你判断并简短说明。宽泛大框会让命中率虚高，请避免把相隔目标塞进一个框。
4. 每图点击“确认本图并下一张”。先完成 5 张也可导出进度；最终各自导出一个 JSON。草稿会尝试保存在本机浏览器，但清理浏览器或换文件位置可能丢失，应及时导出。需要换设备/浏览器时可用“恢复我的 JSON 进度”，只接受同一数据包、同一评审的文件。请保留 JSON 原文件；恢复会用文件替换该评审当前进度，先导出当前工作再恢复。
5. 完成后把两份 JSON 交回当前对话。不要由一个人代替另一人作答。如果暂时只有你一人，先交 A，双人资格保持未完成。

预计操作时间仅作安排参考：每人约 20–40 分钟，可分段完成。没有要求你现在完成一千张。

我收到文件后会做：
- 核对图片 SHA256、数据包身份、评审身份、框坐标与完成情况。
- 分开报告类型一致性、框数分歧、对应框 IoU、疑问与缺失项，不把有分歧的答案自动合成真值。
- 列出需要你们讨论的图片；先解释和调整标注规范，再冻结规范与算法，再建立新的保留集。独立标注指答案来自真实独立评审，并不表示这批开发图片可转成保留集。
- 此试标还不是眼动实验，也不证明真实视觉注视概率。30 张覆盖夜景、自然、人物、产品、设计、艺术各 5 张；没有预先强制填满无焦点/边缘/文字等分层，试标结果会揭示这些缺口。
- 上述类别只是已有素材的检索分组，其中包含历史肖像、静物画和海报，不能据此声称覆盖了现代人脸、真实商品摄影或移动端截图。扩大数据前须重新按实际内容标记分层，而非照搬文件名前缀。

当前已知还需人工看：四颜色人物案例 portrait-124039915 的“未可靠归属”比旧算法增加约 3.5 个百分点。该数值是颜色覆盖指标，不能等同于焦点精度。为避免污染盲评，先做焦点标注，后看质量对照。

数据来源：本包使用已核验授权和 SHA256 的 30 张既有开发图片，原始字节保持不变；每图下方显示作者、来源与许可。packet.json 保存完整出处。浏览器不调用 AI、不上传图像/标注；只有手动点击来源链接才会访问外网。

开发者重建命令：
node scripts/prepare-attention-pilot.mjs <已有授权图像目录> <输出目录>
后续比较命令见仓库 scripts/compare-attention-pilot.mjs 的用法。输出只供分歧复核，不生成声称已验收的 held-out 清单。
