# Third daily-use repair: faithful samples and one analysis pipeline

_Date: 2026-11-03. Baseline: 3c25202._

## Findings and implementation

F07 was caused by using quantized histogram labels as real RGB evidence. [100,150,200] became [104,152,200], and nearby distinct low-color fields could disappear into one bin. Five valid unit regressions fail against the baseline: three non-grid uniform colors, distinct colors sharing a bin and a grayscale clustered mean. The fix retains weighted source-channel sums, using quantization only for grouping. Low-color sampled inputs bypass that grouping. Protected accent centers still represent perceptual hue families; complex-image palettes are not guaranteed to equal literal source pixels.

F06 had a separate root cause: the single-image Worker and series HTMLImage/Canvas path used different decoders/reduction. Both now use the same Worker palette task and `analyzeImagePalette`. Shared settings are versioned 2.0.0. JSON exports retain per-source analysis metadata so later comparisons can identify processing changes; changing the count also refreshes the recorded setting.

F08 was an all-or-nothing batch: a corrupt middle file discarded earlier successful work and skipped remaining files. The new per-file flow retains successes, attempts following files, reports individual failures and allows another import. A valid/broken/valid browser regression reproduced zero imported images on the baseline, then passes with two successes. Existing drafts are unaffected by an all-failed addition. Capacity checks remain explicit, with no silent six-image truncation.

The first full run passed the 50-image operational benchmark and all 30 development images but failed the existing red-into-blue regression: one [51,34,42] pixel was assigned to #1c2333 before denoising. The absolute-distance guard ignored a large hue gap because both colors were dim. Eight new failing regressions cover the observed case, compatible-family fallback and six rotated dim hue families. The fix rejects a hue gap above 75 degrees when both colors have chroma at least 0.02 even below that distance guard; it then uses the existing compatible-family fallback or abstains. The baseline zero-leak requirement is retained. This is still a declared color heuristic, not an independently calibrated semantic classifier.

Reviewing per-image tails after that passing run exposed a second asymmetry: a waterfall's six-color unassigned area rose from the historical 12% to 27.9%. Candidate probes showed that all accent budgets produced the same palette, so adding more seed variants would not address the cause. Assignment treated a 0.033-chroma green candidate as neutral using 0.035, despite treating source hues as meaningful from 0.02. Six positive hue-family counterexamples failed. Aligning candidate/fallback chroma to 0.02 preserves same-hue muted candidates while retaining the new opposed-hue guard. On the identical 8000 original samples, the waterfall's rejected count falls from 2250 to 860 with unchanged nearest-color reconstruction error. Complete corpus results and remaining tails are recorded in the release evidence, not inferred from this one example.

## Verification and limits

Local and public acceptance evidence is recorded separately. The regular suite covers true source-color preview/download, metadata after count changes, single/series resized texture identity, partial/all failures and retry. Five extraction tests augment the existing distribution, denoising, ROI, attention, stale-response and role-state suites. The 50-image benchmark and licensed 30-image development matrix are rerun because the image evidence changed.

Final local result: 178 unit tests in 17 files pass. The complete browser run passes 43 tests: 41 regular workflows plus the two operational image suites; independent human-focus qualification is skipped. Type checking, lint without warnings, environment safety and production build pass. Final 50-image timing is mean 955 ms / p95 1491 ms on this machine; this is not a cross-device performance guarantee. Across the 90 development count settings, unassigned area is on average 2.91 percentage points lower than the earlier pipeline; the largest remaining increase is +3.5 points on portrait-124039915.jpg at four colors. This case remains for human review, not silently excluded or claimed correct by these metrics.

The final additive provenance/export change uses canonical absolute public schema links and matching schema IDs, so a downloaded JSON file and nested provenance references do not depend on the recipient recreating the application's local folder paths. All unit tests and three affected real-download workflows pass after that change; the image algorithm is unchanged from the complete 50/30 run. The local production-build smoke also passes with no page errors, failed resources, API requests or 390px overflow. Actual source-color export, metadata, manual drafts, lock exceptions and partial batch success are verified. Public smoke results are separate release artifacts.

Sampling remains bounded to 8000 decoded nontransparent pixels after a maximum 512px reduction. Shares are estimates; exact proportion assertions use fixtures below the sampling limit. Browser color management, resampling and JPEG decoding remain distinct from reading raw file channel bytes. The pipeline still cannot infer semantic focus or guarantee human aesthetic quality.

## Reflection and revised next steps

The previous suite caught workflow breakage but also encoded historical quantized colors. Passing it did not establish source fidelity or cross-mode equivalence. Fixing code without inspecting the fixture bytes would have preserved the wrong acceptance standard. The first 50/30 run also shows why an aggregate processing pass is not a color-accuracy score: it missed a real one-pixel hue conflict caught by a targeted existing regression. Positive same-family cases are equally necessary: rejecting more pixels can hide wrong-color leakage while making valid regions disappear. Future gates should combine source contracts, targeted positive/negative failure classes, worst-case per-image deltas and independent evidence with real exported files, rather than freezing old outputs or increasing upload counts alone.

State ownership is now the next higher-value risk. Manual overrides survive operations but still disappear on refresh, while reports are invalidated by browsing changes. Another thousand-image run cannot resolve either loss. Next establish a validated, versioned local project record containing source Blobs, extracted evidence, manual overrides, series order/primary/strategy and report snapshots. Restore only after storage is read; never overwrite a saved project with an initial empty render. Storage failures must leave the live draft usable and expose backup/retry.

Then add reversible history over deliberate project edits, separate analysis snapshots from current ROI browsing, and bring preview/export/local colors into the active task. Validate reload, interrupted imports, failed storage, project backup round-trips, undo/redo and phone layout before expanding the dataset. Independent focus evaluation still requires human reviewers and remains the eventual human-input gate; code-generated labels cannot replace it. These next milestones are not claimed complete by this repair.
