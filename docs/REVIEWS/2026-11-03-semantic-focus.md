# Dedicated semantic focus candidate

Subsequent follow-up: the owner accepted the text presentation only, the observed legacy recommendation alias was repaired, and a bounded comparison did not justify automatic deeper/review calls. See [the later comparison record](2026-11-03-priority-comparison.md). The original experiment and remaining-work record below describes the earlier candidate stage; its legacy report-field issue is no longer an unrepaired item on the follow-up branch.

The contrast prototype cannot distinguish a face from a collar or rank a color relationship against a depicted person. This candidate adds an explicit **Analyze subjects and priorities** action backed by the existing configured DeepSeek connection. Deterministic palette and spatial measurements remain local; they do not become semantic object masks or fixation probabilities. No local model or new dependency is required.

## Product and data flow

`POST /api/focus` accepts a compressed original image and fixed full-source measurements: six-color extraction, a spatial raster capped at 512 pixels, and a JPEG capped at 1024 pixels. These settings do not follow the edited palette, application domain or ROI. The dedicated task uses a versioned general prompt, JSON output, a 4096-token output limit and disabled thinking for DeepSeek. It has at most two attempts, no automatic retry on 401/429, the existing route rate limiter, and sanitized failures. The pre-existing aesthetics-report task remains separate and unchanged.

The semantic graph expresses subjects, parts, groups, contours and color relationships with ranked/shared/distributed/no-dominant/uncertain outcomes. Validation rejects missing references, cycles, invalid boxes, contradictory ranked/shared labels and counting a parent plus its descendant as independent primary subjects. A face and clothing can retain meaningful different priorities within one person. These are structural safeguards, not proof that the model understands an image correctly.

The UI defaults to readable text and unpainted imagery. Same-subject details are nested; independent secondary subjects remain visible. A user may request one transparent, explicitly approximate box at a time. A model rectangle is never converted into a focus dot, a segmentation boundary or a human annotation. Local color-contrast evidence keeps its separate label and opt-in display.

Up to ten source-owned focus records persist with project state and backups, including prompt version, model alias/returned model information, server duration, attempts and successful-response token usage. The model alias does not establish its underlying model revision. Existing version-one backups default to an empty focus history. Source replacement clears the active cache and stale responses cannot populate the replacement image; palette edits, domain changes and ROI browsing do not start another focus call. An explicit refresh can create a separate record. A failed refresh preserves the last valid result. These caches are local project history, not a shared cross-user cache or automatic semantic revalidation after a prompt change.

## Real API experiment and decision

Twelve previously inspected development images were prepared with verified original hashes. The API received images and independent measurements, never human answers, case IDs or filenames. All raw responses, input hashes, exact prompt snapshots, licenses, human quotes and comparison pages remain in the private external workspace archive, outside this repository.

- v1: twelve image-only and twelve measured-facts calls; 23/24 passed the strict schema. One response omitted the required uncertainty array. Supplying measured facts did not uniformly improve subject ranking.
- v2: twelve measured-facts calls with a general whole-image comparison prompt; 12/12 passed structure checks. Some duplicate part descriptions decreased, but rank disagreements remained. This is not an across-the-board accuracy improvement.
- Combined-report probe: five images, six requests. Three general reports included structurally valid focus; another general report had contradictory focus priorities, and one image failed the general report schema twice because recommendations used `actionable` instead of `action`. Responses ended normally, not by token truncation. The combined design was rejected. That probe's frozen bundle is historical evidence, not the final implementation.
- Final dedicated-route probe: the actual Hono `/api/focus` handler was bundled and invoked in Node against real DeepSeek HTTP. Twelve images returned 200 with valid semantic structures on their first attempt, about 3.1–4.8 seconds per image in this run. This verifies the candidate handler/provider chain; it is not a deployed Cloudflare test, latency guarantee or 100% semantic accuracy.

The semantic task recovers subjects that contrast alone cannot name, including portrait faces, inverted figures and interacting people. Primary/secondary order remains insufficient: competitive people are sometimes tied, a poster's figure/title can outrank its color relationship, a natural scene can receive overly strong multiple foci, and a held light can remain secondary to its bearer. A repeated same-version invocation also changed some secondary rankings. No per-image rules, human-derived coordinates, accuracy percentages or automatic corrections were introduced to conceal these disagreements. The ambiguous portrait feedback is not treated as a strict no-focus label.

There were 54 HTTP requests across these experiments, reusing twelve development images rather than 54 independent samples. The conservative peak/cache-miss estimate is USD 0.07834 at the documented input/output rates; actual billing, cache hits and time-dependent discounts may differ. The final dedicated twelve-route run accounts for USD 0.01777 of that estimate. Pricing and capability references: [DeepSeek pricing](https://api-docs.deepseek.com/quick_start/pricing/), [vision](https://api-docs.deepseek.com/guides/vision/), [thinking mode](https://api-docs.deepseek.com/guides/thinking_mode/).

These UI replays are distinct from the genuine API route probe. The read-only twelve-card comparison loads 51 embedded images at desktop and phone widths, verifies all twelve original digests and makes no external asset requests. One initial review check could not reach a sandbox-isolated loopback server; restarting the same read-only service in the browser-visible environment resolved it without changing the page policy.

Keep this candidate off production main pending presentation review and better ranking evidence. Existing human preferences remain the development criteria; they do not need to be collected again. Freeze these results, assess whether subject/part hierarchy is understandable, then evaluate a bounded contender or targeted recheck on both the known failure types and fresh images before selecting a ranker. New object detectors or segmentation tools should only address demonstrated localization gaps, not automatically replace semantic ranking. A thousand-image qualification requires a matching output contract, independent samples and actual human annotations where regional metrics are claimed. The existing legacy report-field ambiguity remains a separate reliability issue; splitting the task avoids increasing that report's scope but does not repair its old prompt.
